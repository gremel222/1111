# Настройка постоянной памяти в Arena Agent Mode + GitHub

## Что подтверждено документацией Arena

- В Agent Mode можно подключить GitHub, выбрать репозитории через Manage repositories и включить GitHub toggle.
- В начале сессии Arena создаёт отдельную копию выбранного репозитория в sandbox.
- Изменения отдаются в GitHub через рабочую ветку/commit и Pull Request; их можно просмотреть в Diff и Checks.
- Один Arena-чат сейчас поддерживает создание одного PR.
- После merge или close этого PR текущая сессия больше не может push; новые изменения, оставшиеся только в сессии, не переносятся автоматически в новую сессию.
- Agent Mode поддерживает загрузку Markdown (`.md`) и PDF; полный список поддерживаемых форматов указан в официальной справке.

Официальные страницы:

## Важное различие по AGENTS.md

Arena Agent Mode web docs описывают clone/sandbox/PR workflow, но не дают отдельной гарантии, что `AGENTS.md` автоматически читается каждым выбранным orchestrator-моделем. Поэтому данный комплект использует два уровня защиты:
1. Корневой `AGENTS.md` как переносимый стандарт инструкций проекта.
2. Явный prompt в начале каждой новой Arena-сессии, который просит прочитать этот файл и проверить `Docs/00_START_HERE.md`.

В документации Arena для отдельного Codex/API-подключения есть спецификация `AGENTS.md`, однако не следует автоматически переносить это утверждение на любой режим сайта Arena: https://platform.arena.ai/docs/codex . Проведите одноразовый тест из следующего раздела.

## Одноразовая установка

1. Откройте https://arena.ai/agent/ и выберите Agent Mode / Work.
2. Убедитесь, что GitHub подключён.
3. Откройте Manage repositories и предоставьте доступ только к нужному репозиторию.
4. В Agent Mode включите GitHub connector.
5. Выберите репозиторий и актуальную базовую ветку (`main` или вашу рабочую ветку).
6. Приложите `Docs/01_GAME_PASSPORT.md` из этого пакета. Markdown поддерживается Arena Agent Mode. Если передаёте уже распакованный пакет через локальный GitHub PR, не нужно загружать отдельные файлы.
7. Вставьте текст из `ARENA_BOOTSTRAP_PROMPT.md`.
8. Агент должен создать рабочую ветку, установить документы, сделать commit и открыть один PR. Не разрешайте ему сливать PR без проверки.
9. В Diff проверьте, что `AGENTS.md`, `Docs/00_START_HERE.md`, паспорт и файлы статуса действительно присутствуют в PR.
10. Проверьте Checks, затем merge вручную.

## Проверка постоянной памяти

После merge:
1. Создайте НОВУЮ Arena-сессию с тем же GitHub-репозиторием и уже обновлённой базовой веткой.
2. Вставьте `ARENA_NEW_SESSION_PROMPT.md`.
3. Попросите агента назвать статус проекта, перечислить последние изменения и процитировать конкретные правила из `AGENTS.md`.
4. Сверьте ответ с репозиторием. Если агент не прочитал документы, повторно попросите его открыть их явно. До подтверждения не считайте автозагрузку `AGENTS.md` доказанной.

## Как работать далее

- Для одной связанной задачи — одна Arena-сессия и один PR.
- Используйте `Keep working`, если нужно продолжить ту же задачу в открытой сессии.
- Перед merge убедитесь, что HANDOFF и все необходимые документы уже включены в PR.
- После merge/close не продолжайте рассчитывать на прежнюю сессию как на способ push. Запускайте новую сессию от актуальной ветки.
- Не запускайте две сессии одновременно на одной ветке.
- Не храните секреты, API keys, токены или пароли в `AGENTS.md`, `HANDOFF.md` или других документах.

## Ветка и PR

Рекомендуемый шаблон ветки: `memory/project-context-v1` для первичной установки; далее `feat/<short-task>` или `fix/<short-task>`. Одна сессия — один логический PR. Основную ветку не изменять напрямую.
