# SimulationCore — спецификация первого прототипа

Статус: PARTIAL / Phase 1. Это реализованный испытательный срез, не полный AI Runtime.

## Архитектура

- `Source/CodexOfRules/Public/SimulationCore/Types.hpp` — данные, стабильные ID, схема программы v1.
- `Source/CodexOfRules/Public/SimulationCore/Battle.hpp` и `Private/SimulationCore/Battle.cpp` — авторитетная симуляция без Unreal-заголовков.
- `Source/CodexOfRules/Private/CodexBattleArena.cpp` — UE-адаптер: накапливает время, вызывает такты, показывает примитивы и пишет лог.
- `Tests/SimulationCoreTests.cpp` — native-тесты того же ядра.
- `Tests/SimulationCoreDemo.cpp` — консольный бой без UE.

UE Actor Tick не принимает игровых решений. Он только передаёт время в фиксированный такт 250 мс. Анимации и физика пока не участвуют.

## Подтверждённые уточнения

- U-021 / C-006: Snapshot строится после разрешения текущих действий и обновления состояния, непосредственно перед DecisionPoint.
- U-022 / C-008: резервное поведение зависит от роли героя.

## Такт

1. Увеличить целый Tick.
2. Разрешить действия, объявленные ранее, в порядке CommitTick → SourceID → SequenceNumber.
3. Списать стоимость на COMMIT, применить урон/лечение/защиту.
4. Обновить поверженных и ресурс.
5. Обновить исход боя и восприятие.
6. Построить неизменяемый Snapshot.
7. Если бой продолжается, выполнить DecisionPoint по стабильному ID участника.
8. Объявленные действия исполнятся на следующем такте.

В этом срезе нет отдельной фазы WINDUP: DECLARE на такте N, COMMIT/RESOLVE на N+1. Recovery блокирует новое основное действие до указанного целого такта.

## Правила и цели

- Правила сортируются по убыванию priority; при равенстве сохраняется исходный порядок.
- Первое TRUE и доступное действие выбирается.
- UNKNOWN обычного условия трактуется как FALSE.
- Недоступное действие пропускается с кодом причины: cooldown, resource, recovering, no_known_valid_target, target_unknown_or_stale, out_of_range и др.
- Атака выбирает цель только из свежих знаний наблюдателя: минимальный известный HP → логическая дистанция → стабильный ID.
- Лечение выбирает живого союзника с минимальным процентом HP → дистанция → ID.
- Один участник не выбирает два основных действия за такт.

## Восприятие прототипа

Малая арена даёт участникам свежие наблюдения живых противников каждый такт. Это явное допущение сценария, а не реализация финальной видимости, сканирования или связи. Устаревшие знания не дают цель; мёртвые цели удаляются из наблюдений арены.

## Ролевой fallback

Направление подтверждено U-022. Конкретные алгоритмы пока PROPOSED:

- R-014 Guardian: доступная защита себя → доступная атака → явный пропуск.
- R-015 Healer: лечение наиболее раненого доступного союзника → доступная атака → явный пропуск.
- Raider в тестовом сценарии: доступная атака → явный пропуск.

Fallback не создаёт способность и не запускает скрытый бесконечный Retry.

## Данные и ограничения

- Участники, способности и правила имеют стабильные строковые/числовые ID.
- Program schemaVersion = 1; неизвестная версия или неизвестная способность отклоняются до боя.
- Пока проверяется максимум 64 правила на программу; это технический предел прототипа, не финальный ProgramCapacity.
- HP, ресурс, cooldown и время — целые. Урон округляется вниз с минимумом способности; лечение ограничено maxHp.
- Seed хранится в конфигурации, но случайные решения в этом срезе не используются.

## Что уже проверено native-тестами

Валидация, порядок Snapshot/DECLARE/COMMIT, повторяемость полного трейса, независимость от порядка входных участников, приоритеты, cooldown, UNKNOWN/stale knowledge, выбор цели, один выбор на такт, ролевой fallback, явный пропуск, списание ресурса, защита, лечение, терминальный исход, лимит тактов и целочисленные проценты.

## Что ещё не реализовано

Полный Block Catalog, AND/OR/NOT, переменные, сценарии, граф, перемещение и резервирование слотов, статусы, телеграфы, приказы, Survival Guard, сохранения, replay-файлы, миграции, UMG-редактор, финальный UI/art и UE automation tests.

Нельзя объявлять Phase 1 закрытой только по наличию этого среза. Следующий шаг — проверка сборки/запуска в UE 5.8 на Windows, затем расширение каталога блоков и редактор карточек.
