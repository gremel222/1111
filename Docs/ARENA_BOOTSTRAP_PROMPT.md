# Одноразовый prompt: установить память проекта в GitHub через Arena

Скопируй весь текст ниже в новую Arena Agent Mode сессию с подключённым GitHub-репозиторием. Приложи файл `01_GAME_PASSPORT.md` из этого комплекта, если его ещё нет в репозитории.

--- PROMPT START ---

Ты работаешь в Arena Agent Mode с подключённым GitHub-репозиторием проекта THE CODEX OF RULES / «Свод Правил».

ЗАДАЧА: установить постоянную проектную память и протокол передачи контекста между всеми будущими AI-сессиями. Не начинай разработку игровых механик и не меняй существующий игровой код, кроме минимально необходимого README/документационного оформления.

ОБЯЗАТЕЛЬНО СНАЧАЛА:
1. Определи owner/repository, текущую ветку, HEAD commit и чистоту рабочей копии.
2. Изучи README, существующие AGENTS.md/CLAUDE.md/Copilot instructions и папку Docs. Не перезаписывай существующие файлы до сравнения.
3. Изучи приложенный паспорт. Если в репозитории уже есть более новая версия, сравни и не понижай версию. Не выдумывай статусы утверждения.
4. Составь короткий план и перечисли файлы, которые создашь/обновишь.

УСТАНОВИ В РЕПОЗИТОРИИ:
- корневой AGENTS.md;
- README.md или дополни существующий ссылками на память;
- Docs/00_START_HERE.md;
- Docs/01_GAME_PASSPORT.md — канонический Markdown-паспорт;
- Docs/02_DESIGN_DECISIONS.md;
- Docs/03_CURRENT_STATUS.md;
- Docs/04_OPEN_QUESTIONS.md;
- Docs/05_ROADMAP.md;
- Docs/06_CHANGELOG.md;
- Docs/07_HANDOFF.md;
- Docs/ARENA_SETUP.md;
- Docs/ARENA_NEW_SESSION_PROMPT.md;
- Docs/ARENA_END_OF_TASK_PROMPT.md;
- Docs/templates/ADR_TEMPLATE.md;
- .github/pull_request_template.md.

Если файлы из комплекта переданы в контексте, перенеси их без потери содержания. Паспорт v1.3 должен быть сохранён как канонический Markdown. DOCX/PDF — только экспортные копии. Не вставляй в документацию абсолютные пути из временного sandbox.

КЛАССИФИКАЦИЯ РЕШЕНИЙ:
- CONFIRMED_BY_USER — только прямой выбор/подтверждение пользователя.
- PROJECT_BASELINE — согласованная проектная база, но не прямая цитата пользователя.
- PROPOSED — предложение AI.
- OPEN — нерешённый вопрос.
- PROTOTYPE_PARAMETER — стартовые числа, требующие тестов.
- SUPERSEDED — отменённое старое решение.
Не повышай PROPOSED/OPEN/PROTOTYPE_PARAMETER до CONFIRMED_BY_USER без пользователя.

ОБЯЗАТЕЛЬНАЯ ЛОГИКА ПАМЯТИ:
- AGENTS.md содержит правила, а не полный паспорт.
- 00_START_HERE указывает порядок чтения и источники истины.
- 01_GAME_PASSPORT — полный дизайн.
- 02_DESIGN_DECISIONS — ADR/реестр решений с обоснованием, статусом и датой.
- 03_CURRENT_STATUS — только фактическое состояние реализации, проверенное в репозитории.
- 04_OPEN_QUESTIONS — все нерешённые вопросы.
- 05_ROADMAP — задачи и контрольные точки.
- 06_CHANGELOG — история значимых изменений.
- 07_HANDOFF — короткая передача следующей сессии: что сделано, что проверено, известные проблемы, следующий точный шаг.

КОНТРАКТ КАЖДОЙ БУДУЩЕЙ СЕССИИ:
Прочитать AGENTS.md → 00_START_HERE → 02_DESIGN_DECISIONS → 03_CURRENT_STATUS → 07_HANDOFF → профильные спецификации → проверить реальный код → планировать → реализовать → тестировать → обновить документы → обновить HANDOFF → commit/push/PR.

UNREAL ENGINE:
Проверь, доступны ли в sandbox UE 5.8, Visual Studio/Build Tools, Windows toolchain и графический Unreal Editor. Не утверждай, что Blueprints/UMG открыты или скомпилированы, если среда этого не позволяет. Не создавай выдуманные `.uasset`. Для непроверенных операций ставь NOT RUN и давай пользователю точные ручные шаги.

GITHUB / ARENA:
- Создай отдельную рабочую ветку `memory/project-context-v1` (если имя занято — безопасное уникальное имя).
- Не коммить напрямую в main.
- Эта Arena-сессия должна создать не более одного PR.
- Не сливай PR самостоятельно.
- В PR включи все файлы памяти, необходимые следующей сессии.
- До завершения покажи diff, список файлов, результаты проверок и PR URL.

ПРИЁМОЧНЫЕ ТЕСТЫ:
1. `AGENTS.md` и `Docs/00_START_HERE.md` существуют в целевой ветке.
2. Канонический паспорт присутствует и не обрезан.
3. Все ссылки между локальными Markdown-файлами корректны.
4. Статусы решений различают прямое подтверждение, проектную базу и предложения.
5. CURRENT_STATUS не утверждает непроверенную реализацию.
6. HANDOFF содержит следующий шаг.
7. README ведёт к источнику истины.
8. Нет секретов/токенов в документах.

В ОТЧЁТЕ УКАЗАТЬ:
- repository и branch;
- commit SHA;
- PR URL;
- созданные/обновлённые файлы;
- какие документы конфликтовали и как разрешены;
- какие тесты PASS/FAIL/NOT RUN;
- что осталось открытым;
- точный prompt для новой Arena-сессии.

Не заявляй об успехе, пока изменения не отправлены в GitHub и PR не подтверждён платформой.
